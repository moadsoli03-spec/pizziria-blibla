PLANNED FRONTEND-ONLY REBUILD (localStorage)

This file documents the implementation details that will be applied to:
- js/storage.js
- js/auth.js
- js/menu.js
- js/app.js
- js/cart.js
- js/orders.js
- js/admin.js
- js/api.js

Schema (STRICT):
- localStorage.users
- localStorage.currentUser
- localStorage.products
- localStorage.cart
- localStorage.orders

Checkout MUST create orders in localStorage.orders with:
{
  id,
  userEmail,
  items,
  total,
  status,
  createdAt
}

orders.html MUST filter:
order.userEmail === currentUser.email
Admin sees all orders.

All backend/API/JWT/fetch/Bearer logic must be removed.
js/api.js must become a harmless no-op module.

Implementation steps:
1) storage.js rewritten to be the ONLY localStorage wrapper.
2) auth.js rewritten to manage localStorage.users + localStorage.currentUser only.
3) menu.js + app.js "add to cart" must push to localStorage.cart via STORAGE.addToCart(...) and dispatch "cartUpdated".
4) cart.js rewritten to render from localStorage.cart and do checkout by creating localStorage.orders entries.
5) orders.js rewritten to render from localStorage.orders filtered by current user (admin sees all).
6) admin.js rewritten to manage products and order statuses purely in localStorage.
7) api.js neutralized to remove fetch usage and remove window.API usage patterns.
